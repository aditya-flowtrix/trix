## On your machine

| Command                 | Checks                                                                                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run check`         | generated files in sync with the tokens; conventions (breakpoints, no `px`, no undefined `var()`); colour contrast in every theme; types |
| `npm run seo`           | every page of the build, as a search engine reads it                                                                                     |
| `npm run test:browsers` | every page in every installed browser                                                                                                    |
| `npm run test:cms`      | the CMS importers and the whole import pipeline                                                                                          |

## Every page, every browser

```bash
npm run build
npm run test:browsers                         # every browser installed on this machine
npm run test:browsers -- --browser firefox    # one, or a list: chrome,brave,webkit
```

It finds every page by following links from the home page, and checks each at
375, 768 and 1440 wide:

- no script errors or failed requests;
- no sideways scrolling, no text or table squeezed to nothing;
- unique ids, images with width and height;
- WCAG 2.2 AA with axe;
- the 12-column grid and Spacer measure what they should;
- every component on the page, driven by mouse and keyboard — the skip link,
  nav, accordion, dropdown, tabs, modal, slider, marquee, video and reveal.

The report is `.trix/browsers.md`. Options: `--widths 375,1440`,
`--pages /,/about`.

| Browser                       | How it runs                                                        |
| ----------------------------- | ------------------------------------------------------------------ |
| Chrome, Edge, Brave, Chromium | your installed copy, through Playwright                            |
| Firefox, WebKit               | Playwright's builds — `npx playwright-core install firefox webkit` |
| Safari                        | the real one, on a Mac, through `safaridriver`                     |

Safari needs one setting first: Safari → Settings → Developer → **Allow remote
automation**.

## In CI

Every Trix project has `.github/workflows/ci.yml`, the same workflow the
framework runs. Once the project is on GitHub, it runs on every push and pull
request, and every Monday:

- **Type-check and build** — dependency audit, formatting, `npm run check`,
  the CMS tests, the build, the SEO audit.
- **Browsers** — Chrome, Edge, Brave, Firefox and WebKit on Linux, at the
  same time. A failure uploads the report.
- **Safari** — the real one, on macOS.
- **Astro latest** — the newest Astro, as a warning, never a failure: it says
  when the project needs a look before an upgrade does.

A commit that fails any of them is marked red on GitHub.

<Aside title="Real Safari in a private repository">
  GitHub bills macOS at ten times the Linux rate in a private repository, so
  there the Safari job is skipped and WebKit — Safari's engine — covers it. To
  run it anyway, set a repository variable: Settings → Secrets and variables →
  Actions → Variables → `TRIX_SAFARI` = `on`. Public repositories always run it.
</Aside>
