Every Trix site has a style guide at `/style-guide`: its brand, type, colors,
themes, spacing, layout grid, motion, icons and components on one page, in
numbered chapters with a bar that follows you down it. Each sample is labelled
with the token or class that makes it — click the name to copy it. The sections on this page are
Trix's own, rendered live by the same components.
[See the whole thing](/style-guide).

## It cannot drift

A style guide is usually a second copy of the design system, kept in step by
hand until the day it isn't. Trix's has nothing to keep in step. The page reads
`src/styles/tokens.css` and `themes.css` at build and renders every value from
them — each swatch's hex, each fluid size at 320 and 1440, each theme's roles.
No value is typed into the page, and none is a screenshot.

Change a token and the next build shows it here, in the utilities, in the prop
types, in the Figma variables and in the token reference — all
[generated from the same two files](/docs/system/tokens).

## It is proven on a migration

When a site moves onto Trix, `/trix-style-guide` measures the source as a
browser renders it — every visible element, at seven widths from 320 to 1920 —
and writes the system it finds into the tokens, under Trix names. Nothing is
read from class or variable names, so it works the same on Webflow, Framer,
WordPress or a site that never had a style guide.

Then `scripts/measure/verify.ts` opens the rebuilt `/style-guide` at the same
widths and measures it the same way: every text style's size, line height,
letter spacing and weight, every spacing step, and the grid's margin, gutter
and content width. Anything more than half a pixel off fails. The style guide
is done when every check is identical — on phone (375), tablet (768) and
desktop (1440), and every width measured between.

## The full page

[The full style guide](/style-guide) shows Trix's defaults — what every new
project starts from. It opens on a brand board (the logo, the typeface, the
brand color and its ramp), then one chapter each:

| Section    | What                                                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Brand      | the logo on light and dark, favicon, touch icon and social image                                                                                                                   |
| Typography | every text style with its fluid range, line height, letter spacing and weight, with your own preview text and a screen width slider; rich text; weights, case, wrapping and clamps |
| Colors     | every palette ramp, each theme with the color each role takes, and a contrast checker for any two colors                                                                           |
| Spacing    | the space scale, section space, site margin and gutter, radius                                                                                                                     |
| Layout     | breakpoints, marking the one your screen is in; the 12 columns at each Figma frame width, `Row` and `Col` patterns, `Grid`, containers, aspect ratios                              |
| Motion     | the hover, open and reveal timings, each with a demo that plays on hover or Play, and a reveal you can replay                                                                      |
| Icons      | Phosphor icons and weights, and the project's own SVGs                                                                                                                             |
| Components | every variant of the buttons, eyebrows, choices, fields, cards and icon sizes, and a link to the rest                                                                              |

## With Figma

The same two files generate the Figma variables in `design/tokens/` —
Primitives, Responsive (Desktop and Mobile modes), Text Styles, Theme (Light,
Dark, Brand) and Components — with the code's names: `--space-6` is
`space/6`, `text-style-h2` is the H2 text style. A designer checks a frame
against the style guide by name, not by eye. When the designer changes the
variables, `/trix-design-system` reads them back into the tokens and the style
guide follows on the next build.

Open `/style-guide` beside the Figma file at 375 and 1440 and press

<kbd>Shift</kbd> <kbd>G</kbd>: the grid overlay shows the same columns the frame
is drawn on. [Designers and Figma](/docs/guides/designers-and-figma) has the
rest of the handoff.

## Every client site gets its own

A project started with `npm create trix-astro` has this page from the first
`npm run dev`. `/trix-style-guide` (measuring an old site) or
`/trix-design-system` (from a Figma file, or by asking) then replaces the
tokens with the client's brand: the page is the same, the values are theirs.

There it is `noindex`, with `/components` — `NOINDEX_ROUTES` in
`src/consts.ts`. It is the working reference for the people building and
designing the site, not a page for search results. Only Trix's own style guide
is public.
